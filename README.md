# 🚀 B2B Mini-CRM (MVP) с контролем SLA, Real-time сокетами и геймификацией

**B2B Mini-CRM** — это CRM-система для управления B2B-продажами. Проект спроектирован с упором на **жесткий контроль качества обработки лидов (SLA)**, **мгновенную синхронизацию данных в реальном времени** и **прозрачную геймифицированную аналитику** для мотивации команды менеджеров.

---

## 🎯 1. Бизнес-цели и ключевой функционал

* **Контроль SLA (15 минут):** Автоматическая фиксация просрочки первого ответа менеджера по новому лиду для минимизации оттока клиентов.
* **Real-time Канбан-доска:** Управление сделками через смену статусов (Drag-and-Drop) с мгновенным обновлением интерфейса у всей команды.
* **Управление задачами:** Исключение «забытых» сделок с помощью обязательного планирования звонков, встреч или писем.
* **Геймифицированная аналитика:** Модуль отчетов, формирующий прозрачный рейтинг эффективности менеджеров («Доска почета», KPI по выручке и «Зона риска» по нарушениям SLA).
* **B2B-архитектура:** Разделение сущностей на контрагентов (Companies) и контактных лиц (Customers).

## 2. Аутентификация 
* Базовая JWT аутентификация. Refresh Token ставится бэком через HTTP Only куки, а Access Token хранится в памяти фронтенда.
* В Redis записывается сессия с refresh-токеном, access-токеном и USER ID, отзывается вместе с логаутом или по TTL
* TTL сессии должен быть не менее TTL refresh токена
* Решения мултивкладочной аутентификации из за хранения access в памяти:
    1) при рядовом обновлении /refresh, идёт верификация refresh-токена, access-токен обновляется, перезаписывается в сессию и отдаётся фронту в JSON.
    2) при открытии новой вкладки или обновлении страницы идёт такой же запрос на /refresh без access-токена, идёт верификация refresh-токена, верификация сессии, проверка жив ли ещё текущий сохранённый access-токен, если да - выдаём его, если нет идёт полное обновление как в первом случае
* Таким образом во вкладках один и тот же access, для фронта всё остаётся просто и без BroadCast Channel функционала передачи токена между вкладками и access токен на клиенте хранится только в памяти фронта

## 🗄️ 3. Базы данных

В качестве основной БД используется PostgreSQL. ORM используется **TypeORM**. Структура поддерживает строгие связи (One-to-Many / Many-to-One) и каскадные удаления для поддержания целостности данных. Каждый пользователь системы имеет строго одну роль.
В качестве memcached-хранилища используется Redis для создания сессий аутентификации и кэширования ответов эндпоинтов

---

## 🛠️ 4. Технологический стек
* **Backend:** Node.js (NestJS) + TypeScript
* **ORM:** TypeORM + PostgreSQL
* **Real-time:** Socket.io
* **Scheduling:** Node-cron
* **Cache** Redis
